# Безопасность

Не публикуйте в Issues секретные ключи, токены, приватные ключи, содержимое `.env`, полные диагностические архивы и IP, которые не хотите раскрывать.

Перед сообщением об ошибке можно приложить версию ОС, версию скрипта, название неуспешного этапа и очищенный от секретов фрагмент вывода.

Для сообщений об уязвимостях используйте GitHub. Укажите затронутую версию, условия воспроизведения и возможное влияние. Не публикуйте рабочий эксплойт до исправления.


Если в разделе Security доступна кнопка **Report a vulnerability**, отправьте закрытый отчёт через неё. Иначе создайте Issue только с общим описанием проблемы; не публикуйте секреты, рабочий эксплойт и данные чужих серверов.
